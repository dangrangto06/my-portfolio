Software Testing Practice — Methodologies & Standards
Standard Test Case Architecture

During the testing coursework, each test case was strictly specified with industry-standard fields:

  • Test Case ID: Unique identifier (e.g. TC_AUTH_01, TC_CRUD_05).
  • Test Scenario: Objective of the test (e.g. Verify login rejection with invalid credentials).
  • Pre-condition: Required system state prior to execution.
  • Test Steps: Step-by-step reproduction instructions.
  • Test Data: Input values (valid/invalid emails, boundary characters, special characters).
  • Expected Result: System behavior according to specification documentation.
  • Actual Result & Status: Real outcome recorded (Passed / Failed / Blocked).
REST API Testing with Postman
  • Organized Postman Collections mapped to API endpoints (Auth, Students, Courses, Jobs).
  • Verified standard HTTP status codes: 200 OK, 201 Created, 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found.
  • Validated JSON Response payload structure, schemas, and required fields.
  • Tested Authorization Bearer Tokens and error response headers.
Defect Reporting Template
  • Bug Title: Concise summary of the defect location and symptom.
  • Severity & Priority: Critical / High / Medium / Low.
  • Environment: OS, Browser version, Screen resolution, Build version.
  • Steps to Reproduce: Deterministic step-by-step procedure to reliably trigger the bug.
  • Evidence: Attached screenshots, screen recordings, and network console logs.
